Defect classes seen in this repo (check these specifically each review):

1. **CHANGELOG entries describing things that aren't in the docs.** The changelog is curated prose, easy to over-claim. Verify each [Unreleased] line against the actual document state — e.g. a claimed "at-a-glance block near the top" that doesn't exist as a block.
2. **Pointers to a target that doesn't contain the referenced thing.** A public doc (README) pointing readers at a doc that doesn't contain the referenced rationale — especially when the real content lives in an internal/untracked note. Seen: the licence README sending readers to `NOTICE` for the no-marks clause that actually lives in `LICENSE` §6 (NOTICE only carries copyright + a pointer to LICENSE). Also the *intra-document* variant — a `(§N)` that resolves to a real section which nonetheless doesn't cover the cited convention: §11 cited "the `docs/local/` convention (§1)" but §1 never mentions `docs/local/` (it's a CLAUDE.md convention). So `§N` resolving to a section is not enough — open the section and confirm it actually covers the thing being attributed to it. **Rename-sweep variant:** when a doc's H1/title changes, grep the whole tree for the *old* title string — other docs cite each other by quoted title, not just by path, and those citations strand silently. Seen: harmonising the three H1s to "A File-First Operating Model for Claude Code" left `docs/packaging-as-a-plugin.md`'s subtitle citing the old "A Methodology for Driving Claude Code". (NOTICE intentionally keeps "Claude Code Methodology" as product-name-of-record — not a defect.)
3. **Path/term drift between methodology prose and the live `.claude/` config.** e.g. methodology calls the memory layer `memory/` but `memory: project` resolves to `.claude/agent-memory/`.
4. **Local-config / secrets protection living only in the user's global gitignore, not the repo `.gitignore`.** `settings.local.json` is safe on this machine via `~/.config/git/ignore` but unprotected for any clone.
5. **Incomplete "known carriers" enumerations of the count/range claim.** When a doc claims to *list* every file carrying the `A–O` range or "fifteen" count, run the actual grep and diff it against the list. The add-section SKILL.md listed README/CLAUDE/CHANGELOG/code-reviewer/DoD/plan/project-repo-shape but omitted the per-appendix-file headers (`docs/appendices/{subagents,hooks,skeletons,skills-and-commands}.md` each say "the full A–O index") and `docs/methodology.md:259` ("Appendices A–O"). The index `docs/appendices/README.md` is covered indirectly (step 1 edits it for the entry). An incomplete carrier list in a skill is worse than no list — it gives false confidence and the omitted carriers go stale.
6. **Stale line-number pins in my own memory.** The 06/2026 code-reviewer.md change told me to anchor by heading/symbol not line number, and to date any note tied to today's state. Pre-existing memory still has bare line pins to clean up when next editing those files: `feedback-recurring-defects.md` cites `docs/methodology.md:259` (re-resolve to the heading carrying "Appendices A–O"); `project-plan-archiving.md`'s `~line 85`/`~line 54` are acceptable because they're paired with a stable description and dated to the appendix split. Convert bare pins to anchors as you touch them; don't churn a file just to fix this.

7. **Multi-file reconciliation claims where one file was missed.** When a diff says it reconciled doc A with doc B (or added an item that other docs/intro lines now point at), open *every* named file and confirm the change actually landed in each. Seen 20/06/2026 (feat/doc-site, first review): ADR 0002 §Consequences, the plan Stage 1, and the DoD's own intro ("see the site-build item below") all asserted the Definition of Done gained a scoped MkDocs build check — but no such checklist item was ever added to `definition-of-done.md`. Three forward-references to a referent that doesn't exist. (Re-review 20/06/2026: the scoped "Doc-site build (when touched)" item is now present in the DoD and the three describers are mutually consistent — resolved.) A specialisation of items 1–2: the claim is in the *describing* files, the omission is in the *described* file.
   **Sibling variant — reconcile every *assertion* of an invariant, not just the files the diff names.** When a change weakens/qualifies a repo-wide claim, grep the whole tree for the claim's *other* phrasings; the diff usually fixes the canonical statement and the named companions but strands a paraphrase elsewhere. Seen 20/06/2026 (feat/doc-site re-review): the branch reconciled "no build, no runtime" in CLAUDE.md, the DoD intro, and ADR 0002 (all now say *the source* has no build, the site is an optional build) and even added CI calling itself "first CI in the repo" — but `README.md`'s Dogfooding paragraph still flatly says the repo is "a documentation project (no build or test step …)", unqualified, in the *same file* that now has a "Reading it as a site" build section a few headings up. The paraphrase was pre-existing so it never showed in the diff — grep `git grep "no build"` for all carriers, not just the changed lines.
   **Carrier note — the plan-first trigger lives in four places, and the `/plan` command is the one that drifts.** The "when to plan" criterion is stated in §2 ("Plan only when the task merits it"), the §5 decision matrix "Plan first?" column, the live `.claude/commands/plan.md` (step "Size the task"), and its published Appendix J copy (`docs/appendices/skills-and-commands.md`, also "Size the task"). When the trigger changes, check all four. Seen 20/06/2026 (chore/prose-followups): the diff relaxed §2 and §5 from ">3 files" to "non-obvious approach (refactor/architecture/invariant)" but left `.claude/commands/plan.md` saying "Plan first when the change **spans multiple docs**" — a positive file-count trigger that now contradicts the relaxed §2. Note the asymmetry: the Appendix J copy was *not* stranded, because it keys on trivial-work size ("one-line or single-file change with no invariant in play"), which is compatible. So the live command and its published copy had *diverged* even before this branch — worth a periodic diff of `.claude/commands/*.md` against their Appendix copies.

**Why:** these are the quiet ones — §N and appendix-letter refs are usually correct because they're obviously load-bearing; the prose-accuracy and config-drift mismatches are what slip through.
**How to apply:** don't just check that refs resolve — check that descriptive claims (changelog, README, doc-to-doc pointers) are *true* against current file contents. See [[project-repo-shape]].
